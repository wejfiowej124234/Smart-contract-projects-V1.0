# 五大核心模块 — 技术设计与实现要点

> 行业顶级借贷协议必须全部具备的 5 大核心模块：定义、作用、设计要点与实现细节。供技术评审与开发落地参考。

---

## 总览

| 核心模块 | 作用（必须达成） |
|----------|------------------|
| 1. 借贷与清算核心 | 实现存、借、还、清算，防坏账 |
| 2. 预言机价格系统 | 提供安全价格，防价格攻击 |
| 3. 利率模型系统 | 调节资金供需，防挤兑并产生收益 |
| 4. DAO 治理系统 | 决定参数、升级与风险控制 |
| 5. 可升级与安全体系 | 支持长期迭代并防止被盗 |

---

## 1) 借贷与清算核心（Lending and Liquidation Core）

### 1.1 定义与目标

- **定义**：用户与协议之间「存款、借款、还款」以及「抵押不足时清算」的完整闭环；目标是**实现存、借、还、清算，防坏账**。
- **防坏账**：通过清算阈值（LT）、清算激励（bonus）、部分清算（closeFactor）与储备金/坏账池，将协议层面的未抵押债务控制在可接受范围内。

### 1.2 设计要点

- **入口统一**：所有存/取/借/还由单一 Pool 入口完成，内部调用储备逻辑（ReserveLogic）、风控（RiskEngine）、利率（InterestRateStrategy）；避免多入口导致状态不一致。
- **记账与凭证**：存款用 aToken（或等价凭证）表示并累积利息；借款用 debtToken 表示；储备侧维护 liquidityIndex/borrowIndex，保证利息可复现。
- **清算触发条件**：健康因子 HF &lt; 1（或 &lt; 清算阈值 LT）时可被清算；清算人偿还部分/全部债务，获得抵押品折价+bonus。
- **清算边界**：单次清算受 closeFactor 限制；支持部分清算，避免一次性强制平仓过大；坏账超出储备金覆盖时，有明确坏账处理与会计口径（Treasury/Reserve）。

### 1.3 实现细节（合约/模块）

| 组件 | 职责 | 关键点 |
|------|------|--------|
| **Pool** | supply / withdraw / borrow / repay 入口 | 校验 LTV/LT、调用 ReserveLogic 记账、更新利率、发事件 |
| **ReserveLogic** | 单池/多池记账、index 累积、utilization | cumulateToLiquidityIndex / cumulateToBorrowIndex；与 aToken/debtToken mint/burn 一致 |
| **RiskEngine** | HF、maxBorrow、maxWithdraw、isLiquidatable | 只读计算，供 Pool 与 Liquidation 调用 |
| **Liquidation** | liquidationCall；closeFactor、bonus、坏账入 Treasury | 与 Pool/Reserve 交互，不直接持币 |
| **Treasury / Reserve** | 协议收入、储备金、坏账覆盖 | 坏账核销路径、caps 与权限 |

### 1.4 与当前项目差距

- 当前：仅 supply/withdraw/borrow/repay，无清算、无 aToken/debtToken、无坏账处理。
- 升级后：需补齐 Liquidation、Treasury、凭证代币与 ReserveLogic 的 index 体系。

## 2) 预言机价格系统（Oracle Price System）

### 2.1 定义与目标

- **定义**：为协议提供**安全、可验证、抗操纵**的资产价格；目标是**提供安全价格，防价格攻击**（闪贷、闪电贷+操纵、单源造假等）。
- **防价格攻击**：多源/多类型（Chainlink、DEX TWAP）、心跳与 staleness 检查、偏离阈值与熔断、L2 上 sequencer 宕机防护。

### 2.2 设计要点

- **统一出口**：所有读价通过 OracleRouter（或等价）的 getPrice(asset) / getPrices(assets)，内部路由到主源/备用源，返回统一精度（如 8 decimals）。
- **主源与备用**：主源（如 Chainlink）不可用时，可降级到 TWAP 或备用聚合器；降级策略与触发条件文档化。
- **安全边界**：PriceBoundGuard：单次/短时价格偏离上限、多源价差上限；超过则 revert 或切换源。Heartbeat：超时未更新视为失效。
- **L2**：若部署在 L2，增加 SequencerUptimeGuard，在 sequencer down 期间不采用新区块内价格，避免无效清算或错误敞口。

### 2.3 实现细节（合约/模块）

| 组件 | 职责 | 关键点 |
|------|------|--------|
| **OracleRouter** | getPrice / getPrices；路由、聚合、精度统一 | 仅读；被 Pool、RiskEngine、Liquidation 调用 |
| **ChainlinkAdapter** | 读 Chainlink 聚合器 | minAnswer/maxAnswer、heartbeat 校验 |
| **DexTwapAdapter** | 可选；Uniswap V3 等 TWAP | 窗口、滑点与操纵面评估 |
| **PriceBoundGuard** | 偏离阈值、熔断、最大价差 | 异常时 revert 或返回降级结果 |
| **SequencerUptimeGuard** | L2 sequencer 状态 | 与 L2 官方接口或自建检测配合 |

### 2.4 与当前项目差距

- 当前：无预言机，抵押与债务同币种 1:1。
- 升级后：多资产、跨资产抵押与清算均依赖 Oracle；需至少 1 个主源 + Guard + 文档（目标仓库 docs/12-PROTOCOL-DESIGN §04 预言机）。

## 3) 利率模型系统（Interest Rate Model System）

### 3.1 定义与目标

- **定义**：根据资金利用率（utilization）和可选的其他输入，计算**供给利率**与**借款利率**，并驱动储备侧的 index 累积；目标是**调节资金供需，防挤兑并产生收益**。
- **防挤兑**：高 utilization 时提高 borrow rate、吸引还款或抑制借入，同时提高 supply rate 吸引存款，平滑流动性波动。
- **产生收益**：spread（borrow - supply）与协议费率构成协议收入来源。

### 3.2 设计要点

- **可插拔**：利率由独立合约 InterestRateStrategy 实现，Pool 只调用 getSupplyRate(getBorrowRate)(utilization, …)；可替换为线性、kink、多段曲线，无需改 Pool。
- **与储备一致**：ReserveLogic 在每次资金变动后调用策略更新 rate，并据 rate 与时间差更新 liquidityIndex/borrowIndex；index 与利率曲线一致，避免套利或会计错误。
- **参数边界**：斜率、kink 点、最大/最小 rate 由配置或治理设定；变更走 PoolConfigurator + Timelock，避免频繁或恶意改动。

### 3.3 实现细节（合约/模块）

| 组件 | 职责 | 关键点 |
|------|------|--------|
| **InterestRateStrategy** | getSupplyRate(utilization)、getBorrowRate(utilization) | 可多实现：线性、kink、多段；参数化 |
| **ReserveLogic** | updateInterestRates；cumulateToLiquidityIndex/cumulateToBorrowIndex | 与策略返回值、时间差一致；gas 与精度（WadRay） |
| **Pool** | 在 supply/withdraw/borrow/repay 后触发 rate 与 index 更新 | 不直接算利率，只调策略与 ReserveLogic |

### 3.4 与当前项目差距

- 当前：利率公式内嵌在 SimpleLending，简单 utilization 线性。
- 升级后：独立 InterestRateStrategy + ReserveLogic index 体系；可支持 kink、多段与不同资产不同策略。

## 4) DAO 治理系统（DAO Governance System）

### 4.1 定义与目标

- **定义**：通过链上提案、投票与延迟执行，对**参数、升级与风险控制**做出决策；目标是**决定参数、升级与风险控制**，避免单点中心化与即时滥用。
- **典型决策**：LTV/LT/bonus、利率策略、上新资产、储备因子、紧急下调参数；实现合约升级（若升级权委托给 Timelock）。
- **治理币**：投票权通常由**治理币**（Governance Token，ERC20）提供；持币或质押量决定提案权与投票权重；治理币不参与借贷池抵押/借出，仅用于治理与可选激励。完整设计见《08-DAO治理-设计清单》。

### 4.2 设计要点

- **提案 → 投票 → 执行**：Governor 负责提案与投票；通过后进入 Timelock 队列，delay 届满后由 Timelock 执行（调用 PoolConfigurator、ProxyAdmin 等）。
- **权限边界**：PoolConfigurator 仅 Timelock（或明确指定的 Admin）可调；ProxyAdmin 所有者建议为多签或 Timelock；Guardian 仅 Pause/紧急参数，不持有升级权。
- **紧急路径**：Guardian 可 emergencyPause、setAssetFrozen、紧急下调 LTV 等，与「正常治理」分离，文档化触发条件与事后审查。

### 4.3 实现细节（合约/模块）

| 组件 | 职责 | 关键点 |
|------|------|--------|
| **Governor** | propose、castVote、queue、execute | 与 Timelock 集成；quorum、投票期、timelock delay 可配置 |
| **Timelock** | executeTransaction、delay | 唯一有权调用 PoolConfigurator/ProxyAdmin 的地址（或与多签组合） |
| **AccessControl** | 角色：DEFAULT_ADMIN、PAUSER、GUARDIAN、CONFIGURATOR | 最小权限；CONFIGURATOR 仅 Timelock |
| **EmergencyModule** | emergencyPause、setAssetFrozen、setLTVEmergency | 仅 Guardian；记录操作与原因 |

### 4.4 与当前项目差距

- 当前：仅 Owner + Pause。
- 升级后：Governor + Timelock + 角色分离 + 紧急模块；参数与升级均走治理或明确文档化的多签流程。

## 5) 可升级与安全体系（Upgradability and Security System）

### 5.1 定义与目标

- **定义**：通过代理模式与安全机制，在**不迁移用户状态**的前提下更换实现逻辑，并**防止合约与资产被盗**；目标是**支持长期迭代并防止被盗**。
- **长期迭代**：bug 修复、新功能（如新资产类型、新利率曲线）通过升级实现合约完成；代理地址不变，用户与前端仍对代理交互。
- **防止被盗**：重入防护、SafeERC20、权限隔离、Pause、审计与形式化验证、监控告警。

### 5.2 设计要点

- **代理选型**：TransparentProxy（Admin 与实现分离）或 UUPS（升级逻辑在实现内）；选定后统一升级流程（见本包《12-升级流程》）。
- **存储布局**：新实现只能追加存储变量，不得在已有插槽前插入或重排，否则代理状态错乱。
- **安全机制**：ReentrancyGuard、Pausable、AccessControl、SafeERC20；关键路径不信任外部回调；Oracle/利率/清算的输入校验与边界条件文档化。
- **审计与验证**：内部 checklist、外部审计、不变量测试、Fuzz；升级前必须通过回归与升级专项测试。

### 5.3 实现细节（合约/模块）

| 组件 | 职责 | 关键点 |
|------|------|--------|
| **ProxyAdmin** | upgrade、upgradeAndCall | 所有者建议多签/Timelock；仅升级代理实现，不直接持币 |
| **TransparentProxy / UUPSProxy** | delegatecall 到实现；保持地址与存储 | 用户仅与代理交互；实现可更换 |
| **实现合约** | Pool、PoolConfigurator、Liquidation 等 | 无构造函数状态写入（用 init 且仅一次）；存储布局兼容 |
| **安全库/修饰器** | ReentrancyGuard、Pausable、SafeERC20、Errors | 统一错误码与事件，便于监控与审计 |

### 5.4 与当前项目差距

- 当前：无代理、无升级能力。
- 升级后：全核心入口经代理；升级流程、回滚与验收成文（见《12-升级流程》）。

## 6) 五模块依赖关系（简要）

```
                    ┌─────────────────────────────────────────┐
                    │  5. 可升级与安全体系（代理 + 权限 + 审计）  │
                    └─────────────────────┬───────────────────┘
                                          │ 承载
  ┌───────────────────────────────────────┼───────────────────────────────────────┐
  │  1. 借贷与清算核心 ◄──────────────────┼──────────────────► 4. DAO 治理系统   │
  │  Pool / Reserve / Liquidation / Treasury│                   Governor/Timelock  │
  └─────────────────────┬─────────────────┴───────────────────┬─────────────────┘
                        │ 依赖价格与利率                         │ 决定参数与升级
                        ▼                                       ▼
  ┌─────────────────────────────┐               ┌─────────────────────────────┐
  │  2. 预言机价格系统           │               │  3. 利率模型系统             │
  │  OracleRouter / Guard       │               │  InterestRateStrategy       │
  └─────────────────────────────┘               └─────────────────────────────┘
```

- **借贷与清算核心** 依赖 **预言机**（价格）与 **利率模型**（index 与 rate）；受 **DAO 治理** 约束（参数、配置）；运行在 **可升级与安全体系** 之上（代理、Pause、权限）。
