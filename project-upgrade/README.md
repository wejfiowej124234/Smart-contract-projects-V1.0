## 防遗漏：完成一部分就要跑测试，再进入下一步

为避免 AI 升级过程中漏掉内容或跳过验证，请遵守以下**执行纪律**（可复制给 AI 使用）：

1. **每完成一个 P 阶段**（或该阶段内的一批「交付物」），**必须先执行该 P 的「打勾测试」**（含脚本测试、部署、冒烟等），**全部通过后再进入下一 P**。不得在未跑完/未通过当前 P 测试的情况下开始下一 P。
2. **测试方式**：以《11-升级阶段清单-P0至P10》中该 P 的「打勾测试」列表为准；通常包括但不限于：`npx hardhat test`、`npm run deploy:localhost`、`npm run smoke:e2e`、以及该 P 要求的单元/集成/权限测试。每项打勾前需实际执行并确认通过。
3. **若文档某处不够细**：以 **03、05、07**（及该 P 相关的 02/06/08/09）中的设计为准补全实现细节，不得自行省略或猜测与设计不一致的行为。有歧义时先查 **00-术语与约定** 或 **13-审计与对照**。
4. **不要跳阶段**：P0→P1→…→P10 顺序固定；除非文档明确标注「可选」，否则不跳过任何 P。

**你可以这样对 AI 说（直接复制）：**

> 请按《11-升级阶段清单-P0至P10》从 P0 到 P10 一步步执行升级。**每完成一个 P 的「升级内容」和「交付物」后，必须跑完该 P 的「打勾测试」**（例如 npx hardhat test、部署、smoke、该 P 要求的单元/集成测试），**全部通过后再进入下一个 P**。不要跳阶段，也不要未通过测试就进入下一阶段。若某处文档不够细，以 03/05/07 等设计文档为准补全，有歧义查 00 或 13。
