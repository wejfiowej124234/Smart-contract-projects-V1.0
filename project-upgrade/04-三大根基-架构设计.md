# 三大根基 — 架构层级与设计

> 从「架构层级」再抽象一次：行业顶级借贷协议可压缩为**三大根基**。本文定义每层包含内容、设计原则与对五大核心模块的映射。供架构评审与分层实现参考。

---

## 总览

| 根基 | 包含内容 |
|------|----------|
| 金融逻辑层 | 借贷、清算、利率 |
| 安全可信层 | 预言机、安全机制、升级 |
| 治理演进层 | DAO、参数控制、长期升级 |

---

## 1) 金融逻辑层（Financial Logic Layer）

### 1.1 定义与范围

- **定义**：协议中与**资金流动、风险暴露与收益分配**直接相关的逻辑，抽象为「金融逻辑层」。
- **包含内容**：**借贷**（存、取、借、还）、**清算**（触发条件、部分清算、奖励、坏账）、**利率**（利用率→利率、index 累积、收益分配）。

### 1.2 设计原则

- **状态一致**：所有影响用户仓位与池子流动性的操作，必须经过统一入口（Pool）与统一记账（ReserveLogic），避免多路径导致账目不一致。
- **可验证**：利率与 index 的推导可由链上数据复现；清算条件（HF、LT）与清算结果（资产守恒、坏账归属）可审计。
- **边界清晰**：本层不直接依赖「谁有权改参数」「价格从哪来」的实现细节，仅依赖「参数接口」与「价格接口」；具体由安全可信层与治理演进层提供。

### 1.3 与五大核心模块的对应

| 三大根基 | 对应五大模块 |
|----------|----------------|
| 金融逻辑层（借贷、清算、利率） | **1. 借贷与清算核心**（存借还清算、防坏账）<br/>**3. 利率模型系统**（调节供需、防挤兑、产生收益） |

### 1.4 实现与接口要点

- **入口**：Pool — supply / withdraw / borrow / repay；Liquidation — liquidationCall。
- **内部**：ReserveLogic（记账、index）；RiskEngine（HF、maxBorrow、maxWithdraw、isLiquidatable）；InterestRateStrategy（getSupplyRate、getBorrowRate）。
- **输出**：事件（Supplied、Withdrawn、Borrowed、Repaid、Liquidated）；aToken/debtToken 余额与 index；Treasury/Reserve 状态。

## 2) 安全可信层（Security & Trust Layer）

### 2.1 定义与范围

- **定义**：为金融逻辑层提供**可信输入**与**运行时保护**，并支持**逻辑迭代而不丢失状态**的架构层。
- **包含内容**：**预言机**（安全价格、防操纵）、**安全机制**（重入防护、暂停、权限、SafeERC20、输入校验）、**升级**（代理、实现可换、存储兼容）。

### 2.2 设计原则

- **不信任单点**：价格不依赖单一来源或单笔交易；多源/心跳/熔断/sequencer 防护。
- **最小权限**：关键操作仅限特定角色；升级权、配置权、紧急权分离并文档化。
- **可恢复**：异常时可 Pause 止损；升级可回滚到上一实现；关键操作有日志与监控。

### 2.3 与五大核心模块的对应

| 三大根基 | 对应五大模块 |
|----------|----------------|
| 安全可信层（预言机、安全机制、升级） | **2. 预言机价格系统**（安全价格、防价格攻击）<br/>**5. 可升级与安全体系**（长期迭代、防被盗）中的「安全」与「可升级」 |

### 2.4 实现与接口要点

- **预言机**：OracleRouter.getPrice(asset)；ChainlinkAdapter、DexTwapAdapter、PriceBoundGuard、SequencerUptimeGuard（L2）。
- **安全机制**：ReentrancyGuard、Pausable、AccessControl、SafeERC20；Errors/Events 统一；输入校验与边界条件。
- **升级**：ProxyAdmin + TransparentProxy/UUPS；实现合约无构造函数状态、存储布局兼容；升级与回滚流程（见《12-升级流程》）。

## 3) 治理演进层（Governance & Evolution Layer）

### 3.1 定义与范围

- **定义**：决定**参数、风险控制与长期演进**的决策与执行层；谁可以改什么、通过什么流程、在什么条件下执行。
- **包含内容**：**DAO**（提案、投票、执行）、**参数控制**（LTV、LT、利率策略、资产上下架、储备因子等）、**长期升级**（实现合约升级的提议与执行、Timelock 延迟）。

### 3.2 设计原则

- **链上可验证**：提案内容、投票结果、执行 calldata 与执行结果均在链上；参数变更与升级操作可追溯。
- **延迟与可逆性**：关键操作经 Timelock 延迟，给监控与社区反应留窗口；紧急路径（Guardian）与正常治理分离，且事后可审计。
- **边界清晰**：治理层只调用「配置入口」（如 PoolConfigurator）与「升级入口」（ProxyAdmin），不直接改金融逻辑层的内部状态。

### 3.3 与五大核心模块的对应

| 三大根基 | 对应五大模块 |
|----------|----------------|
| 治理演进层（DAO、参数控制、长期升级） | **4. DAO 治理系统**（决定参数、升级与风险控制）<br/>**5. 可升级与安全体系**中的「可升级」的执行流程（提议→投票→Timelock→upgrade） |

### 3.4 实现与接口要点

- **DAO**：Governor（propose、castVote、queue、execute）；Timelock（executeTransaction、delay）。
- **参数控制**：PoolConfigurator（initReserves、setLTV、setLiquidationThreshold、setInterestRateStrategy、setReservePause 等）；仅 Timelock 或指定 Admin 可调。
- **长期升级**：ProxyAdmin.upgrade / upgradeAndCall 由 Timelock 或多签执行；升级流程、验收与回滚见《12-升级流程》。

## 5) 层级依赖与调用关系

```
                    治理演进层
              DAO / 参数控制 / 长期升级
                         │
                         │ 配置与升级调用
                         ▼
                    安全可信层
              预言机 / 安全机制 / 升级（代理）
                         │
                         │ 价格、权限、Pause、代理委托
                         ▼
                    金融逻辑层
                  借贷 / 清算 / 利率
                         │
                         │ 用户与清算人调用
                         ▼
                    用户 / 前端 / 机器人
```

- **金融逻辑层**：被用户与清算机器人直接调用；依赖安全可信层提供的**价格**（预言机）、**权限与暂停**（安全机制）、**代理委托**（升级后的实现）。
- **安全可信层**：被金融逻辑层在运行时依赖（读价格、检查 Pause、执行 delegatecall）；被治理演进层通过 ProxyAdmin/PoolConfigurator 间接驱动（升级、参数）。
- **治理演进层**：不直接处理资金；仅调用配置器与升级管理合约，且通常经 Timelock 延迟执行。
