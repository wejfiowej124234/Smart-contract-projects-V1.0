### 1.2 P0–P10 中前端相关打勾分布

| 阶段 | 前端相关交付物/打勾 | 对应 §10 |
|------|---------------------|----------|
| **P0** | 前端可完成 supply→borrow→repay→withdraw（当前 Demo） | 基线验收 |
| **P1** | 前端/测试使用代理地址 | 集成点 |
| **P5** | 前端集成：多资产 UI、aToken/debtToken、代理地址；**前端高标准（§10）**：§10.1 全局框架与路由、§10.2 Dashboard（Your Supplies/Borrows、HF 卡、Liquidation Price、Borrow Power）、§10.2–§10.3 Markets 与交易弹窗、§10.3 状态机与 Before/After 风险预览、§10.4 风控可视化 | §10.1–§10.4 |
| **P9** | 前端验收：治理 UI 可查看提案、投票、执行状态；**前端高标准（§10）**：治理 UI 与 §10.2 一致（提案列表/详情、投票、执行）；若共用导航含 §10.1 | §10.2 Governance、§10.1 |
| **P10** | 前端集成验收；**前端顶级标准验收（高标准必选）**：§10.1–§10.4 与 P5/P9 一致；§10.5 数据与刷新；§10.6 错误处理与可恢复；§10.7 安全与合规 UX；§10.2 Activity、Settings；§10.8 Dev Panel（可选） | §10.5–§10.8、Activity、Settings、Dev Panel |

### 1.3 覆盖缺口与建议

| 项 | 说明 | 建议 |
|------|------|------|
| **§10.2 Governance 在 P10 的显式引用** | P10 前端顶级标准验收已列「§10.2 Activity、Settings」，未显式写「§10.2 Governance（提案列表、详情、投票、执行、创建提案可选、委托投票可选）」；P9 已含治理，但 P10 全量验收时宜显式列出 | 在 11 P10「前端顶级标准验收」中增加「**§10.2 Governance**（提案列表、详情、投票、执行；创建提案/委托投票可选）」 |
| **代币/分析看板（波浪图）** | 《前端升级方案》§8 有「代币/分析看板：价格、波浪图、时间周期切换（可选）」；11 P5/P10 未显式写该条 | 在 11 P10「前端顶级标准验收」中增加「**代币/分析看板（可选）**：价格、价格+成交量波浪图、时间周期切换，见《前端升级方案》§8」 |

**结论**：P0–P10 **已通过「以《前端升级方案》§10 为准逐条打勾」覆盖绝大部分前端升级内容**；仅 **§10.2 Governance 在 P10 的显式列出** 与 **代币/分析看板（可选）** 两处建议在 11 中补写，实现时仍以《前端升级方案》§10 与 §8 为唯一验收依据。

## 二、文档合并与删除建议

### 2.1 当前文档清单（project-upgrade 根目录 + archive）

| 类型 | 文件 | 说明 |
|------|------|------|
| **入口与约定** | README.md、00-术语与约定.md | 必保留；README 为入口，00 为术语与顺序权威 |
| **编号 01–15** | 01～15 共 15 个 .md | 主文档包，按 00 约定与 README 表使用；**建议全部保留** |
| **无编号** | 迁移方案-占位.md、前端升级方案.md、UI-UX设计方案.md、前端企业级审计报告.md、全面审计报告.md | 迁移占位、前端方案与设计、审计报告；**建议全部保留**（README/00 已引用） |
| **归档** | archive/ 内：审计与问题清单.md、参考文档覆盖对照表.md、archive/README.md | 已合并入 13-审计与对照，仅作历史保留；**建议保留 archive 现状，不删除** |

### 2.2 合并建议

| 建议 | 说明 |
|------|------|
| **不合并** | 00–15 与无编号文档职责清晰：00 术语、01–02 基线、03–09/15 设计、10–12 执行、13–14 审计；前端升级方案/UI-UX/前端企业级审计/全面审计 分别为前端方案、设计、前端审计、综合审计入口。合并会削弱「按编号查阅」与「审计溯源」的清晰度。 |
| **可选合并（不推荐）** | 若强烈希望减少文件数，可考虑：**全面审计报告** 与 **14-企业级审计报告** 合并为「14-企业级审计报告」，在 14 内设「全面审计」章节——但两者受众不同（全面=顺序+内容+前端+缺口，14=清晰度+缺口+文档关系），**建议保持两文件独立**。 |

**结论**：**不建议合并**现有主文档；保持 00–15、README 与 misc/ 内无编号文档（迁移方案-占位、前端升级方案、UI-UX设计方案、前端企业级审计报告、全面审计报告等）独立，便于按编号与用途查阅。

### 2.3 删除建议

| 文件/目录 | 建议 | 理由 |
|-----------|------|------|
| **archive/** 内文件 | **不删除** | 已归档，README/13 已说明「原两文件已移至 archive」；保留便于历史追溯。 |
| **00–15、README** 与 **misc/ 内过程文档（约 24 个）** | **不删除** | 均为当前有效主文档或审计/方案文档，被 00/README 或交叉引用。 |
| **重复或废弃文档** | **无** | 当前未发现与本包约定冲突的重复文档；审计与问题清单、参考文档覆盖对照表 已归档而非删除。 |

**结论**：**无需删除**任何现有文档；archive 内为历史归档，根目录及无编号文档均为在用文档。
