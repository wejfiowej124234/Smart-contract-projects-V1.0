# P1–P8 深度检查报告（对照升级文档与顶级系统配置）

> 对照《07-升级后智能合约清单》《06-升级后目录结构》《02-资产清单》《09-安全设计-清单》《12-升级流程》及 11 各 P 的升级内容，对当前 P1–P8 实现进行**深度检查**，列出与「顶级系统配置」及升级文档标准的差距及整改建议。

**检查结论概要**：
- **功能层面**：P1–P8 打勾测试已通过，核心能力（代理、利率、Pause、Configurator、aToken/debtToken、Oracle、清算、不变量/Fuzz、清算脚本）已具备。
- **文档标准层面**：与 07 合约清单、06 目录结构、02 多资产与 config 驱动、09/12 完整落位相比，存在**多项缺口**；当前形态为「单资产、最小可用、合约平铺」，尚未完全对齐「行业顶级高级 DeFi 借贷」的文档约定。
- **整改优先级**：高（影响审计与交付一致性的）→ 中（影响可维护性与多资产扩展）→ 低（可选或 P9/P10 补齐）。

## 六、整改建议（按优先级）

### 6.1 高优先级（影响与文档/审计一致性）

1. **07 与实现对齐**  
   - 在 Pool 上增加 **getReserveData**（或明确以 getPoolInfo + 单 reserve 等价说明），以及 **getUserAccountData** 或正式将 getUserPosition 在文档中映射为「等价 getUserAccountData」。  
   - 在 PoolConfigurator + Pool 上增加 **setReservePause(asset, paused)**，与 07 一致。

2. **12 §7 首次部署前检查**  
   - 在目标仓库建立 **docs/08-deployment-runbook.md**（或等价），内含 12 §7 首次部署前检查清单，并可打勾；部署前强制阅读/打勾。

3. **02/15 config 驱动部署**  
   - **deploy.ts** 改为读取 `scripts/config/reserves.<chainId>.json`（或环境变量指定路径），按 config 调用 initReserve/setLTV/setLiquidationThreshold 等，使「资产清单与参数」与 02、15 §2.C 一致。

### 6.2 中优先级（影响可维护性与多资产扩展）

4. **06 目录结构**  
   - 将合约按 **contracts/core/**、**contracts/tokens/**、**contracts/oracle/**、**contracts/libs/**、**contracts/interfaces/** 迁移；测试按 **test/unit/**、**test/integration/**、**test/invariants/**、**test/fuzz/** 迁移；scripts 按 **scripts/deploy/**、**scripts/config/**、**scripts/ops/** 整理（保留现有 config 与 deploy 逻辑，便于 config 驱动）。

5. **ReserveLogic 与 Treasury**  
   - 增加 **reserveFactor** 与 **mintToTreasury** 路径（ReserveLogic 或 Pool 在利息/手续费路径中调用 Treasury）；Treasury 增加 **setReserveFactor**（或由 PoolConfigurator 写 Pool/Treasury），与 07 一致。

6. **UserConfiguration**  
   - 多资产扩展时实现 **UserConfiguration** 库及 **setUserUseReserveAsCollateral**；当前单资产可在文档中注明「多资产时补齐」。

### 6.3 低优先级（可选或 P9/P10）

7. **07 其他项**  
   - getNormalizedIncome/NormalizedDebt：可在 ReserveLogic 或 Pool 上以 view 暴露，与 07 一致。  
   - Errors/Events 库：统一错误码与事件名，便于审计与前端。  
   - validateBorrow/validateWithdraw：在 RiskEngine 或 Pool 上暴露为 view，供前端/链下使用。

8. **Oracle**  
   - DexTwapAdapter、SequencerUptimeGuard 按 07/04 在主网或多链/L2 部署时补齐。

9. **liquidation-bot/**  
   - 将 **scripts/run-liquidation-bot.ts** 迁至 **liquidation-bot/** 并配 src/、strategies/ 等，与 06 一致；或保留脚本并在文档中说明「最小可用在 scripts/」。

10. **09 §4 §6、monitoring、audits**  
    - 在 P10 或发布前补齐：09 清单打勾、monitoring/alerts、audits/ 目录、08-runbook 与应急流程。

## 七、总结表

| 维度 | 是否按升级文档/顶级配置 | 说明 |
|------|--------------------------|------|
| 07 合约清单 | ⚠️ 部分 | 核心已有；缺 getReserveData、getUserAccountData、setReservePause、mintToTreasury、UserConfiguration、Treasury.setReserveFactor、Errors/Events、DexTwap、SequencerUptimeGuard |
| 06 目录结构 | ❌ 未对齐 | 合约/测试/脚本未分子目录；无 liquidation-bot/、monitoring/、audits/、formal-verification/ |
| 02 资产与 config | ⚠️ 部分 | 单资产；config 存在但未驱动部署 |
| 09 安全 | ⚠️ 部分 | §2 主要防护已落位；§4 §6 与清单打勾未全做 |

| P1–P8 功能打勾 | ✅ 已通过 | 各 P 打勾测试已执行并通过 |

**结论**：P1–P8 在**功能上**满足 11 打勾与核心能力，但在**与 07/06/02/09/12 的文档约定和顶级系统配置**上存在明显差距。建议按上述优先级逐项整改，并在 P9/P10 前完成高、中优先级项，以便与「行业顶级高级 DeFi 借贷」的文档标准一致。
