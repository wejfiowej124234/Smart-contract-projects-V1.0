# 前端完整架构级 UI/UX 重构方案（Aave 级 · 可直接落地）

> **事实源**：以当前已完成的 **v1.0 Enterprise-Grade Local-Only** 协议为唯一事实源。  
> **设计标准**：按 Aave 级产品设计（Markets + Dashboard 分层、资产数据可视化、治理进度可视化、app/admin 双端、企业级信息层级与暗色主题）。  
> **约束**：不改变合约与 **p10:gate** 门禁闭环（不改 deployments 契约、不改 CI/evidence-pack 依赖）。  
> **产出**：可直接落地到代码结构与组件划分的完整前端重构方案。

## 1. 事实源与约束

### 1.1 唯一事实源

| 维度 | 内容 |
|------|------|
| **协议版本** | v1.0 Enterprise-Grade Local-Only（P0–P10 已完成） |
| **合约** | LendingPoolImpl（代理）、PoolConfigurator、Oracle、Governance（GovernorP9 + Timelock）、SimpleLending 兼容层等；前端通过 **代理地址** 调用，地址来自 **frontend/src/contracts/deployments.json**（由 deploy 经 scripts/_lib/export.ts 自 deployments/\<chainId\>.json 同步，与 docs/09 一致） |
| **门禁** | `npm run p10:gate` 从零起链 → p10:ci → evidence-pack；**前端重构不修改** 脚本/evidence 契约、不新增对 GitHub/release 的依赖 |
| **前端现状** | 单层 `frontend/src/`：App.tsx、Layout、DashboardPage、MarketsPage、GovernancePage；hooks（useDashboard、useActions、useWallet、usePoolInfo 等）；components（layout/actions/dashboard/tx/ui/admin/charts）；config/contracts/state/utils/types；已有 design-tokens、三主题（light/dark/dark-navy）、Markets 页与 PriceVolumeChart、治理提案列表+投票+ETA |

### 1.2 不可变更项

- **合约接口与部署产物**：不增删合约方法、不改变 `deployments/*.json` 字段语义；前端继续读 **frontend/src/contracts/deployments.json** + ABIs（与 docs/09 一致）。

- **链与配置**：仍为 local-only（chainId 31337）；RPC、链名、合约地址来源保持 config/network + deployments。

### 1.3 可变更项

- **前端目录结构**：由单层 `src/` 可重构为 **app/**（用户 DApp）+ **admin/**（治理/管理）+ **shared/**（共享），或保持单入口在 `src/` 内用**逻辑分层**（见 §4）。
- **UI/UX**：布局、主题 Token、页面结构、图表、治理可视化、路由与导航均可按 Aave 级方案升级。
- **组件与状态**：新增/拆分组件、共享 hooks、设计系统实现均在前端内部完成。

## 2. 设计标准总览（Aave 级）

| 维度 | 标准 |
|------|------|
| **信息层级** | 关键指标（HF、总供应/借入、APY）首屏大字号/高对比；次要信息折叠或收拢；数字等宽、右对齐、小数位与链上一致 |
| **暗色主题体系** | 主背景深色、卡片/图表分层（bg-page / bg-card / bg-elevated）；语义色（success/warning/danger）；焦点环不依赖纯色 |
| **Markets vs Dashboard** | **Dashboard** = 你的组合（你的供应/借入、HF、净 APY、快捷操作）；**Markets** = 市场储备列表（每资产 Supply/Borrow APY、流动性、利用率、LTV/LT），从 Markets 进入供应/借入 |
| **资产数据可视化** | 价格+成交量双轴图（波浪图）；时间周期 1d/1w/1y；可置于资产详情或代币分析看板；数据可模拟或后续接 subgraph/预言机 |
| **治理进度可视化** | 提案列表：状态 Tag（Active/Pending/Queued/Executed）、For/Against/Abstain 票数、Timelock ETA；提案详情：投票进度条、执行倒计时、投票/执行按钮 |
| **app / admin 双端** | **app**：普通用户（Dashboard、Markets、资产详情、治理查看/投票）；**admin**：治理/运营（提案列表/详情、创建提案、执行、可选 Pause/参数只读） |
| **企业级体验** | 统一错误映射、Toast+可展开详情、Loading Skeleton、空态插画+CTA、高风险操作二次确认、交易弹窗状态机（Approve→Confirm→Pending→Success/Fail） |

## 4. 可直接落地的目录与代码结构

以下为**两种落地形态**：A）保持单层 `src/` 的**逻辑分层**（最小改动）；B）**物理分层** app/admin/shared（与 06 目标形态一致）。

## 5. Markets 与 Dashboard 分层设计

### 5.1 数据与职责划分

| 层级 | 数据来源 | 职责 |
|------|----------|------|
| **Dashboard** | useDashboard(provider, account, chainId) | 当前用户：余额、池子快照、仓位（supplied/borrowed/healthFactor/maxWithdraw/maxBorrow）；展示「你的供应/借入」、HF 卡、Risk & Parameters 折叠面板、快捷操作入口 |
| **Markets** | usePoolInfo(provider, chainId) + 可选 reserve 列表 | 市场级：总供应/总借入、利用率、supplyRate/borrowRate；展示**所有可供应/可借入资产**列表（当前为单资产 USD8），每行：资产、Supply APY、Borrow APY、流动性、利用率；CTA 跳 Dashboard 或弹窗供应/借入 |
| **AssetDetail** | usePoolInfo + useTokenMetadata + 单 asset | 单资产详情：APY、LTV/LT（可从 config 或只读合约读）、价格+成交量图表（PriceVolumeChart） |

### 5.2 页面结构（Aave 对齐）

- **Dashboard 首屏**：顶部 KPI 条（总供应、总借入、健康因子、净 APY 可选）；下方 Your Supplies / Your Borrows 表或卡片；Health Factor 卡（三色+阈值说明）；Risk & Parameters 折叠；Actions 区（Supply/Withdraw/Borrow/Repay）；底部 Contracts 折叠。
- **Markets 首屏**：筛选（全部/供应/借入）可选；市场级 KPI 可选（Total liquidity、Total borrows）；储备列表表格或卡片（资产、Supply APY、Borrow APY、总流动性、利用率）；每行「Supply」「Borrow」跳转或打开同一套 PreflightModal 流程；右侧或下方可嵌「Pool activity」价格+成交量图（已有 PriceVolumeChart）。

### 5.3 组件划分（可直接对应文件）

| 功能 | 组件/页面 | 建议文件位置 |
|------|-----------|--------------|
| Dashboard 容器 | DashboardPage | app/pages/DashboardPage.tsx 或 pages/DashboardPage.tsx |
| KPI 条 | DashboardKpiBar | shared/components/dashboard/DashboardKpiBar.tsx（或 app/components/） |
| 你的供应/借入 | UserPosition + PoolOverview | 已有 shared/components/dashboard/ |
| 风险面板 | RiskParametersPanel | 已有折叠块于 DashboardPage；可拆为 shared/components/dashboard/RiskParametersPanel.tsx |
| Markets 容器 | MarketsPage | app/pages/MarketsPage.tsx |
| 储备列表 | ReserveList / MarketCard | shared/components/markets/ReserveList.tsx，或内联于 MarketsPage |
| 资产详情 | AssetDetailPage | app/pages/AssetDetailPage.tsx；内嵌 PriceVolumeChart |

## 6. 资产数据可视化（图表）

### 6.1 组件与数据流

| 组件 | 职责 | 数据 | 位置 |
|------|------|------|------|
| **PriceVolumeChart** | 价格曲线 + 成交量柱状图，双 Y 轴；1d/1w/1y 切换 | 当前为前端模拟序列；后续可接 subgraph 或链上事件聚合 | shared/components/charts/PriceVolumeChart.tsx |
| **AssetChartSection** | 包装 PriceVolumeChart + 标题 + 时间 Tab | 用于 Markets 页「Pool activity」、AssetDetail 页、代币分析看板 | shared/components/charts/AssetChartSection.tsx（可选） |

### 6.2 技术要点

- 图表库：已用 **Recharts**（ComposedChart + Area + Bar）；保持不增加新依赖或可替换为 Lightweight Charts。
- 主题：图表颜色使用 CSS 变量（`--color-primary`、`--color-border`、`--color-textMuted`），随 `[data-theme]` 切换。
- 无障碍：Tooltip 提供数值与名称；可选在图表旁提供「近期价格/涨跌」文字摘要（aria-describedby）。

### 6.3 与事实源一致

- 不依赖新合约方法；历史价格/成交量可为**模拟数据**或占位，不影响 p10:gate 与 evidence-pack。

## 8. app / admin 双端结构

### 8.1 路由设计

| 路径 | 布局 | 说明 |
|------|------|------|
| `/` | AppLayout | Dashboard |
| `/markets` | AppLayout | Markets |
| `/markets/:assetId` | AppLayout | 资产详情（可选） |
| `/governance` | AppLayout | 治理（列表+投票） |
| `/admin` | AdminLayout | 重定向到 /admin/proposals |
| `/admin/proposals` | AdminLayout | 提案列表（管理视角） |
| `/admin/proposals/:id` | AdminLayout | 提案详情（Queue/Execute） |

### 8.2 布局与门禁

- **AppLayout**：顶部 AppHeader（钱包、网络、主题）+ AppNav（Dashboard | Markets | Governance）+ `<Outlet />`；PauseUnpauseBar 仅在有权限且为 Pauser 时显示（逻辑不变，不依赖新合约）。
- **AdminLayout**：顶栏 AdminHeader（返回 app 链接、网络、钱包）+ 侧栏或 Tab（Proposals）+ `<Outlet />`。**不新增链上门禁**；admin 仅为前端路由与 UI 区分，权限仍由合约（Governor/Timelock、Pauser）控制。

### 8.3 与 p10:gate 的关系

- p10:gate 不校验「是否具备 /admin 路由」；仅校验链上部署、CI、evidence-pack。前端 E2E 若存在，可仅覆盖 app 侧主流程（Supply/Borrow/Repay/Withdraw + 治理查看）；admin 为可选增强，不强制纳入 gate。

### 9.2 暗色主题强制与可选

- 默认或首选：**暗色**（`data-theme="dark"` 或 `dark-navy`），与 Aave 风格一致；保留 light 切换（与现有 useTheme 一致）。
- 对比度：正文与背景 ≥4.5:1，大字 ≥3:1（WCAG 2.1 AA）；焦点环使用 `--focusRing`，不单靠颜色。

### 9.3 组件规范（简要）

- **数字**：等宽字体、右对齐；金额与资产 decimals 一致；APY/百分比 2–4 位小数；健康因子 2 位。
- **核心指标卡**：大数字 + 单位 + 短标签；HF 危险区间用语义色+图标。
- **表格/列表**：表头固定（桌面）、行 hover、空态与 Loading 统一。
- **按钮/输入**：主按钮高对比；加载中 disabled + loading 图标；危险操作用 danger 变体。

### 11.1.1 Front-end Upgrade Plan – F6–F10（Product Hardening & Tech UI）

以下五段将「工程实现说明」升级为**产品发布规范**，达到最终发布级别。

**F6 视觉系统与科技风 UI 规范**

- **设计语言**：深色基底、霓虹强调色、玻璃拟态/微发光边框、网格背景（可选）
- **Design Tokens**：
  - color（bg/surface/border/text/accent/warn/success）
  - radius（8/12/16）
  - shadow（soft + glow）
  - spacing（4/8/12/16/24/32）
  - typography（标题/数值/正文/辅助）
- **组件状态规范**：loading / empty / error / disabled / success；skeleton、toast、inline-error、retry
- **可访问性**：focus ring、键盘导航、对比度、aria-label

**F7 数据可信与「非真数据」标注策略**

- **强制标注规则**：凡是模拟数据/占位数据 → UI 必须显示 "Simulated / Placeholder"
- **数据来源面板**（可选但很加分）：当前 chainId、合约地址、oracle 状态、最后刷新时间
- **链上读取失败的用户友好提示**："合约未部署 / Oracle 未配置 / RPC 不可用 / 网络不支持"；每条错误提供「重试 / 切回 31337 / 打开诊断」按钮

**F8 Activity / History / Notifications（把「占位」变成可用）**

- **Activity（交易历史）**：本地 txStore + onchain event（或仅 txStore 先做 MVP）；字段：time、type、asset、amount、txHash、status；支持筛选（All / Pending / Success / Failed）
- **通知中心（MVP）**：交易提交/确认/失败 toast + history 中可追踪

**F9 产品级交互与体验补齐**

- **页面跳转「可返回」**：Back 行为一致（浏览器返回/面包屑）
- **空状态**：未连接、无仓位、无提案、无历史 → 提示 + CTA
- **输入体验**：金额输入防抖、最大值、精度处理、错误提示不闪烁
- **移动端/响应式**：断点（sm/md/lg），主导航在 mobile 下变为底部栏或抽屉
- **性能**：React memo、useMemo/useCallback 规则；避免无限渲染（已踩过的 #185）

**F10 发布级验收与门禁**

- **验收定义**：
  - Business-Closure（A1–F17）= 真实点击证据 + E2E=0
  - Full Release（p10:gate）= exit 0 + evidence-pack + sha256 + 四锚点
- **必须通过的测试**：`npm run e2e:ui` exit 0；`npm run p10:gate` exit 0
- **证据产物**：forensic 截图 + forensic-evidence.json；evidence-pack（manifest sha256、summary 四锚点）
