# 升级方案：从当前 Demo 到行业顶级高级 DeFi 借贷

> 目标：在保留「可复现、可验收」的基础上，将本仓库升级为现实世界行业顶级的高级 DeFi 借贷协议形态（架构、合约、目录、模块化、链下配套均对标 Aave/Compound 级）。

---

## 1) 升级原则

- **渐进式**：按阶段交付，每阶段可独立验收、可回滚。
- **模块化**：核心池、利率、清算、预言机、治理、代理分离，接口清晰，便于审计与替换。
- **安全优先**：先上代理与权限边界，再上多资产与清算；利率/预言机/清算均需单元测试 + 不变量 + 审计证据。
- **链上/链下协同**：链上合约与链下 Keeper/清算机器人/Subgraph/监控一并规划，避免「只有合约无运维」。

---

## 2) 阶段划分

### 阶段 0：基线（当前）

- 2 个合约：TestToken、SimpleLending。
- 单资产、无预言机、无清算、无治理、无代理。
- 见《01-当前项目现状》。

**验收标准**：见《11-升级阶段清单-P0至P10》P0 打勾项（测试通过、部署与前端可跑通、文档已就绪）。

### 阶段 1：核心拆分与可升级底座（约 4–6 周）

**目标**：在「单资产」不变的前提下，把逻辑拆成「池子入口 + 储备/利率库 + 代理」，为后续多资产与清算打基础。

- **合约**：
  - 引入 **代理**：TransparentProxy 或 UUPS，SimpleLending 改为实现合约，通过代理调用。
  - 拆出 **ReserveLogic**（或同名库）：资产池记账、utilization、accrual、index；当前 SimpleLending 内 updateRates/updateUserPosition 逻辑迁入。
  - 拆出 **InterestRateStrategy** 接口 + 单策略实现（当前公式）：由 Pool 调用，便于后续替换为 kink 曲线。
  - **Pool.sol**：保留 supply/withdraw/borrow/repay 入口，内部调 ReserveLogic + InterestRateStrategy；LTV 检查保留在 Pool 或拆到 RiskEngine 库。
- **治理**：引入 AccessControl，角色至少 Admin/Pauser；Pause 权限与 Owner 分离。
- **部署**：deploy 脚本改为部署「代理 + 实现 + 策略」，导出地址与 ABI；保留单资产（如 USD8）与现有前端兼容模式。
- **测试**：现有 8 个集成用例保留并通过；新增代理升级流程测试、角色权限测试。

**交付物**：可升级的「单资产池」+ 独立利率策略 + 文档（部署/升级 runbook）。  
**验收标准**：现有 8 个集成用例通过；代理升级流程测试通过；角色权限测试通过；部署与升级 runbook（见本包《12-升级流程》）就绪。

### 阶段 2：多资产与 aToken/debtToken（约 4–6 周）

**目标**：从单资产扩展为多资产市场，存款/借款用凭证代币表示，支持利息累积与转让。

- **合约**：
  - **PoolConfigurator**（或等价）：上线/下架资产、改 LTV/LT/利率策略地址等；仅治理+Timelock 可调。
  - **aToken**：存款凭证，利息累积（基于 index），可 transfer；Pool supply 时 mint，withdraw 时 burn。
  - **debtToken**（variable/stable 二选一或兼有）：借款凭证，与 borrow/repay 挂钩。
  - **ReserveLogic** 扩展：按 reserve 维度维护 state（index、liquidity、debt、utilization），Pool 多资产路由。
  - **UserConfiguration**：用户级「哪些资产作抵押/哪些作借款」位图，支持隔离模式（可选）。
- **风险参数**：每资产 LTV、Liquidation Threshold、Liquidation Bonus、cap；RiskEngine 库统一计算 HF、maxBorrow、maxWithdraw。
- **测试**：多资产 supply/borrow/repay/withdraw、利息累积、隔离仓边界、参数配置器权限。

**交付物**：多资产池 + aToken/debtToken + 配置器 + 风险参数文档。  
**验收标准**：多资产 supply/borrow/repay/withdraw 集成测试通过；利息累积与隔离仓边界测试通过；PoolConfigurator 权限测试通过。

### 阶段 3：预言机与价格层（约 3–4 周）

**目标**：引入价格依赖，支持「抵押资产 ≠ 借出资产」及后续清算。

- **合约**：
  - **OracleRouter**：统一出口 getPrice(asset)，内部路由 Chainlink / TWAP / Fallback。
  - **ChainlinkAdapter**：读 Chainlink 聚合器， decimals/heartbeat 校验。
  - **DexTwapAdapter**（可选）：Uniswap V3 TWAP 等。
  - **PriceBoundGuard**：偏离阈值、熔断、最大价差；异常时 revert 或 降级策略。
  - **L2**：若上 L2，增加 SequencerUptimeGuard。
- **集成**：Pool/RiskEngine 使用 OracleRouter 获取价格，计算 collateralValue、debtValue、HF。
- **测试**：价格获取、熔断、心跳过期、多源一致性与单元测试。

**交付物**：Oracle 路由 + 至少 1 个主源 + Guard，文档（**目标仓库** docs/12-PROTOCOL-DESIGN.md §04 预言机；或本包内预留章节）。

### 阶段 4：清算模块（约 4–5 周）

**目标**：HF &lt; 1（或 &lt; LT）可被清算，部分清算、奖励、坏账处理符合行业惯例。

- **合约**：
  - **Liquidation**（或库）：清算入口，closeFactor、部分清算、collateral 折价与 bonus；与 Pool/Reserve 交互。
  - **Treasury/Reserve**：协议收入、储备金、坏账覆盖（bad debt 处理流程）。
  - 可选：**拍卖**接口（清算资产拍卖给第三方）。
- **风险**：清算激励与 MEV 平衡；Gas 与复杂度；需不变量测试（资产守恒、HF 边界）。
- **链下**：清算机器人（监控 HF、提交清算 tx），策略可含 flash loan、私有 mempool。
- **测试**：单元清算、不变量、Fuzz、fork 主网/L2 回放（可选）。

**交付物**：清算合约 + Treasury + 清算机器人最小可用版 + 目标仓库 05-liquidation-design.md。

### 阶段 5：治理与紧急（约 2–3 周）

**目标**：参数与配置通过治理+Timelock 执行，紧急情况 Guardian 可 Pause/限流。

- **合约**：
  - **Governor**：提案、投票、执行（或与现有 Governor 兼容）。
  - **Timelock**：延迟执行，PoolConfigurator/关键参数仅 Timelock 可调。
  - **AccessControl**：Gov / Guardian / Pauser / Configurator 角色边界清晰。
  - **EmergencyModule**：紧急暂停、单资产冻结、参数紧急下调（仅 Guardian）。
- **流程**：参数变更 = 提案 → 投票 → Timelock 排队 → 执行；目标仓库 docs/12-PROTOCOL-DESIGN.md §07（升级与治理）。

**交付物**：Governor + Timelock + 权限与紧急流程文档。  
**验收标准**：至少一次「参数变更」经 Governor 提案 → 投票 → Timelock 执行成功；Guardian 可 Pause/Unpause；权限与紧急流程文档就绪（见《11-升级阶段清单-P0至P10》P9 打勾项）。

### 阶段 6：Flash Loan、跨链与进阶（按需）

- **Flash Loan**：白名单/费率/单次额度上限；与 Pool 流动性复用，风险控制文档化。
- **跨链**：BridgeAdapter / MessageReceiver，跨链流动性或消息（可选，视资源）。
- **合规与审计**：威胁模型、审计证据包、Bug Bounty、形式化验证报告（Certora/Halmos 等）。
- **默认**：先单链主网，L2 与跨链按需。

**P10 与本地发布**：P10 = Engineering-Complete（本地离线交付）。**最终验收**：`npm run p10:gate`（含 deploy → governance → e2e:ui → evidence-pack）exit 0；e2e:ui 失败则门禁 exit 1。见《11-升级阶段清单-P0至P10》P10 及路径 A。

---

## 3) 依赖关系（简要）

- 阶段 1 为底座，2/3/4/5 可部分并行但建议顺序：1 → 2（多资产）→ 3（预言机）→ 4（清算）→ 5（治理）。
- 阶段 3 为阶段 4 清算的前置（需价格）；阶段 5 可与 2/3/4 重叠（先上 AccessControl，再上 Governor/Timelock）。

---

## 4) 风险与缓解

| 风险 | 缓解 |
|------|------|
| 升级引入新 bug | 每阶段完整测试 + 不变量 + 代理升级演练 |
| 清算/预言机被攻 | 多源/熔断/心跳 + 审计 + 监控告警 |
| 治理中心化 | Timelock + 多签 + 文档化权限边界 |
