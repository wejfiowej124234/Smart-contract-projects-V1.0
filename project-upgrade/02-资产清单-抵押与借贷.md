# 资产清单：抵押资产与借贷资产

> 本文定义**哪些代币可作为抵押**、**哪些代币可被借出**，以及清单的维护位置与配置方式。升级前后均需可追溯、可打勾验收。

---

## 1) 当前项目（升级前）— 基线清单

当前为**单资产**协议：同一代币既作抵押也作借出资产。

| 类型 | 代币 | 说明 |
|------|------|------|
| **抵押资产** | USD8 | 唯一。用户 supply 的即为抵押品，与借出资产同币种。 |
| **借贷资产** | USD8 | 唯一。用户 borrow 的即为 USD8；无跨资产借贷。 |
| **仅展示** | WETH | 前端展示余额，**不参与**协议抵押/借贷。 |

- **链上来源**：`contracts/SimpleLending.sol` 构造函数绑定单一 `token`（USD8 地址）；无「资产列表」合约状态。
- **部署来源**：`scripts/deploy/deploy.ts` 部署 USD8、WETH、SimpleLending；仅 USD8 传入 SimpleLending。
- **治理币**：治理币（Governance Token）仅用于治理投票与激励，**不参与**池子抵押/借出；定义与清单见《08-DAO治理-设计清单》。

## 2) 升级后 — 资产清单的形态与来源

升级后为**多资产**：抵押资产与借贷资产由「储备（reserve）配置」决定，每类资产可有不同 LTV、LT、利率策略等。

### 2.1 清单应包含的字段（设计）

| 字段 | 说明 |
|------|------|
| **资产** | 底层代币（如 USDC、WETH、USD8）；合约地址 + 链 |
| **是否可抵押** | 是否可 supply 并作为抵押品参与 HF 计算 |
| **是否可借出** | 是否可 borrow；若可借出则池子需有该资产流动性 |
| **LTV** | 贷款价值比（如 75 表示最多借抵押价值的 75%） |
| **清算阈值 LT** | 低于此 HF 可被清算（如 80 表示 80%） |
| **清算奖励 bonus** | 清算人获得的抵押品折价比例 |
| **利率策略** | InterestRateStrategy 合约地址 |
| **预言机** | 价格来源（Oracle 中该资产对应 feed/源） |
| **储备因子 / cap** | 可选；协议收入比例、单资产上限等 |

### 2.2 清单的存放位置（升级后仓库）

- **链上**：由 **PoolConfigurator.initReserves**（及后续 setLTV/setLiquidationThreshold 等）写入；链上为**唯一真实来源**。
- **链下配置**：建议在 **scripts/config/** 下用结构化文件维护，便于部署与审计对照，例如：
  - `scripts/config/reserves.<chainId>.json`（本仓示例：**reserves.31337.json**）：每链、每资产的参数；部署脚本通过 **loadProfile(chainId)** 取 profile，储备路径由 **profile.reservesConfigPath** 指定（本仓 mock 见 configs/profiles/mock/profile.json），未指定时回退为 scripts/config/reserves.\<chainId\>.json；读取后调用 initReserves / setLTV 等。与 **docs/09-本地链标准与地址** Part 2 §3、Part 3 §3 一致。
  - `docs/asset-list.md`（或本包内 **02-资产清单-抵押与借贷** 的「升级后」章节）：人类可读的**抵押资产清单**与**借贷资产清单**，与 config 对齐并注明「以链上为准」。

### 2.3 升级后示例表（占位，按实际上线填写）

以下为**示例**；实际上线资产以治理与 scripts/config 为准。

| 资产 | 可抵押 | 可借出 | LTV | LT | 说明 |
|------|--------|--------|-----|-----|------|
| USD8 | ✅ | ✅ | 75% | 80% | 当前 Demo 延续；测试网/本地 |
| WETH | ✅ | ✅ | 82% | 85% | 示例；主网常用 |
| USDC | ✅ | ✅ | 77% | 82% | 示例；稳定币 |

- **抵押资产清单**：上表中「可抵押 = ✅」的即抵押资产。
- **借贷资产清单**：上表中「可借出 = ✅」的即借贷资产；用户只能借池子已支持的借出资产。

## 3) 与现有文档的关系

- **01-当前项目现状**：描述「单资产、USD8 同时为抵押与借出」；本文 1) 节与之一致并表格化。
- **10-升级方案 / 11-P0–P10**：P4/P5 多资产与 aToken 阶段，需明确「首批上线哪些资产」；以本文 2) 节及 scripts/config 为准。
- **07-升级后智能合约清单**：PoolConfigurator.initReserves 负责「上线资产」；资产清单由配置 + 本文文档化。
- **03-五大核心模块 / 04-三大根基**：不枚举具体代币，仅说明「多资产、按 reserve 配置」；具体代币列表在本文与 config 中。

## 4) 验收与维护

- **升级前**：打勾确认「当前仅有 USD8 为抵押与借贷资产、WETH 仅展示」与《01-当前项目现状》一致。
- **升级后**：
  - [ ] 链上：通过 Pool 或 PoolConfigurator 可查到的 reserve 列表与本文（或 docs/asset-list）一致。
  - [ ] 链下：scripts/config 中 reserves 配置与本文表格一致；部署/治理变更时同步更新本文或 docs/asset-list。
  - [ ] 前端/文档：展示的「支持的抵押资产」「支持的借贷资产」与链上一致。

**结论**：抵押资产与借贷资产清单在**当前**仅隐含在代码（单资产 USD8）；**升级后**应在本文档（或目标仓库 docs/asset-list）与 scripts/config 中显式维护，并与链上 reserve 配置对齐，便于逐项打勾与审计。
