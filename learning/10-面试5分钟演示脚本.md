## 0) 面试官说“请介绍下项目”时

你可以直接这样开场：

"我做的是一个可复现的 DeFi 借贷 Demo，部署在 Hardhat 本地链 31337。合约用 Solidity + OpenZeppelin，前端用 React + TypeScript + ethers v6。核心是完整的存款/借款/还款/取款流程，并且 UI 通过监听合约事件做自动刷新，同时有交易状态机和刷新兜底，保证演示可靠。"

（停 1 秒）
"我用 3 分钟演示一遍全流程，再用 1 分钟讲两个技术亮点。"

---

## 1) 演示前（10 秒，提前准备好）

如果你是线上面试：
- 浏览器已打开前端页面
- MetaMask 已连到 Hardhat Local（31337）
- 终端里 Hardhat node 正在跑

你只需要说：

"我这边已经把本地链和前端跑起来了，接下来我直接从 UI 演示交易流程。"

备选（Plan B，救场用）：
- 如果 MetaMask 临场抽风，我会立刻运行 `npm run smoke:e2e` 用导出的 ABI/地址完成同样的链上闭环（approve→supply→borrow→repay→withdraw），并把输出作为“闭环证据”。

---

## 2) 连接钱包（30 秒）

边点边说：

"先连接 MetaMask。这里会显示当前 account 和 chainId。如果网络不对，会提示切换到 31337，并且按钮会禁用，避免用户在错误网络上发交易。"

（指一下页面里的 chainId/地址展示）

---

## 3) Supply（存款）（60 秒）

边操作边说：

"我先做 Supply。因为是 ERC20，所以第一步通常需要 approve 授权。这里我做了授权流程的处理：
- 会先检查 allowance，够就跳过 approve；
- 不够则先 approve，再 supply。
交易状态会从 Signing → Pending → Confirmed。"

（看到 confirmed 后）

"确认后 UI 会自动刷新，不需要手动点刷新。这个刷新主要靠监听 Supplied 事件触发，同时交易 confirmed 后也会再触发一次 refresh 作为保险。"

（成功标志提醒一句，面试官更好打勾）
- 你能看到 Tx 行 `signing → pending → confirmed`，并且 supplied 数字变化。

---

## 4) Borrow（借款）（50 秒）

"接下来 Borrow。这里有 LTV 限制：最大可借是 supplied 的 75%。UI 会展示 maxBorrow，并且合约侧也会 enforce：超过会 revert。"

（借款成功后）

"借完后你会看到 borrowed 变大，同时 health factor 会变化。"

（成功标志）
- borrowed 增加、health factor 数值/颜色变化。

---

## 5) Repay（还款）（45 秒）

"还款也需要 allowance 检查，因为 repay 用 transferFrom 把币转回合约。流程同样是：不够 allowance 先 approve，再 repay。"

（确认后）

"还款后 health factor 会变高。"

（成功标志）
- borrowed 下降、health factor 变高。

---

## 6) Withdraw（取款）（45 秒）

"最后 Withdraw。Withdraw 的关键在于不能把仓位提到不健康：
合约里会计算 withdraw 后新的 supply 是否还能覆盖当前 borrow 的 LTV；如果不满足会直接 revert。"

（成功后）

"你可以看到 supplied 下降，余额回到钱包。"

（成功标志）
- supplied 下降，USD8 余额回升。

---

## 7) 技术亮点（60 秒）

挑 2 个点，按下面话术说就行：

### 亮点 A：事件驱动刷新 + 兜底
"我把事件监听作为主刷新路径，满足题目要求，同时加了一个节流的区块监听作为兜底，处理 provider 重连或事件偶发丢失，避免 UI 卡死。兜底不会成为主逻辑。"

### 亮点 B：交易状态机 + 持久化 + Post-state check
"我把交易做成状态机：Signing/Pending/Confirmed/Failed/Stuck，并把 pending 交易持久化到本地存储，刷新页面也能恢复追踪。同时 confirmed 后会做一个短时间的 post-state read 来验证状态变化；如果 RPC 延迟读不到，会标记 unverified 而不是误报失败。"

（一句证据点，防追问）
- 状态机：`frontend/src/state/tx.ts`；pending 持久化：`frontend/src/state/txStore.ts`；事件刷新：`frontend/src/hooks/useDashboard.ts`
