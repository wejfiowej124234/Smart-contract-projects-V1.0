## 0) 通用：30 秒自证闭环（所有岗位都建议）

- 必跑命令：`npm run smoke:e2e`
- 你要说的话（1 句话）：
  - “这个脚本会复用导出的 ABI/地址跑完整 approve→supply→borrow→repay→withdraw，OK 就证明 Part 1 + 合约交互闭环没问题。”
- 证据：录屏里出现 `OK: approve→supply→borrow→repay→withdraw...`

如果 UI 临场翻车（MetaMask 弹不出、切链失败、缓存问题），直接用这条救场。

## 1) 前端岗（React/TS/ethers v6）证据包

### 1.1 必演示步骤（5 分钟内）

1) Connect：点击按钮才弹 MetaMask（避免页面加载就弹窗）
2) 自动切链到 31337（或一键切链按钮可用）
3) Dashboard：余额 + pool + position + maxBorrow/maxWithdraw 都能展示
4) Supply：点击 Supply 后先出现预确认弹窗，确认再打开钱包；allowance 不够会先 approve 再 supply（两步交易）
5) Real-time：交易 confirmed 后 UI 自动刷新；事件监听也能触发刷新

### 1.2 必截图/录屏证据（最小集）

- 图 1：页面已连接（显示 `account` 与 `chainId=31337`）
- 图 2：Dashboard 区块（balances/pool/position/maxBorrow/maxWithdraw 有数字）
- 图 3：Supply 的 tx 状态（至少出现 `pending → confirmed`）
- 图 4：Supply 后 position 的 `supplied` 变大（证明 refresh 成功）
- 图 5：事件监听证据（可用“页面不刷新也更新”的录屏片段，或在 Hardhat node 里看到事件/交易日志）
- 图 6：`npm run smoke:e2e` 输出 OK（Plan B 兜底）

### 1.3 60 秒话术（背下来就够）

- “前端用 ethers v6，读写分离：读链用 provider 不弹钱包，写链用 signer 才会弹签名。”
- “交易统一走 `runTxDetailed` 状态机：signing/pending/confirmed/failed/stuck，能处理超时和替换交易。”
- “数据刷新三层：confirmed 后强制 refresh（最可靠）+ 合约事件监听 refresh（题面必需）+ block/backfill 兜底防漏事件。”

### 1.4 源码定位（面试官追问就点这里）

- 钱包连接/切链/持久化：`frontend/src/hooks/useWallet.ts`（`ensureCorrectNetwork`）
- 仪表盘读链 + 事件刷新：`frontend/src/hooks/useDashboard.ts`（`scheduleRefresh` + `lending.on/off`）
- 表单与预确认：`frontend/src/hooks/useDashboardForm.ts`、`frontend/src/hooks/usePreflight.ts`、`frontend/src/components/ui/PreflightModal.tsx`
- 写链动作 + approve-if-needed：`frontend/src/hooks/useActions.ts`
- 交易状态机底座：`frontend/src/state/tx.ts`（`runTxDetailed`）
- 错误归一化：`frontend/src/state/errors.ts`（`normalizeError`）

## 2) 合约岗（Solidity/Hardhat/Security Awareness）证据包

### 2.1 必演示步骤（5 分钟内）

1) `npm run node`（即 `npx hardhat node`）启动本地链
2) `npm run deploy:localhost` 部署 + seed + 导出（证明 Part 1）；若需治理页有数据，再执行 `npm run deploy:p9`。**正式验收**：端口 8545 空闲下 `npm run p10:gate` 至 exit 0 + evidence-pack 四锚点（见根 RELEASE_CHECKLIST_P10、docs/03-08-deployment-runbook §8）。
3) 解释核心约束（LTV=75%）与 revert 文案对照
4) 演示 1 个成功路径 + 1 个失败路径（revert case）
5) 演示测试：`npm test`（8 个 integration tests，见 test/integration/SimpleLending.integration.ts）

### 2.2 必截图/录屏证据（最小集）

- 图 1：deploy 输出（或生成的 `deployments/31337.json` / `frontend/src/contracts/deployments.json`）
- 图 2：Hardhat node 终端打印交易（supply/borrow/repay/withdraw 至少一笔）
- 图 3：revert case 的测试通过（或测试输出里包含 revert 断言）
- 图 4：合约关键 view（`getPoolInfo/getUserPosition/calculateMaxBorrow/calculateMaxWithdraw`）存在（可截图代码或调用结果）

### 2.3 60 秒话术（背下来就够）

- “这是单币种简化借贷：用户 supply 作为抵押，borrow 受 LTV=75% 约束，healthFactor 用来表达安全边界。”
- “合约提供 view：poolInfo/position/maxBorrow/maxWithdraw，前端只需要读这些就能做 dashboard。”
- “安全意识：使用 OZ 的基础 hardening（Ownable/Pausable/ReentrancyGuard/SafeERC20），不扩展题面功能，只体现工程安全习惯。”

### 2.4 源码定位

- 合约：`contracts/core/LendingPoolImpl.sol`（前端 ABI 名 SimpleLending）、`contracts/tokens/TestToken.sol`；完整结构见 [项目总览架构](项目总览架构.md) §4
- 部署 + seed + 导出：`scripts/deploy/deploy.ts`（`seedTo` + `SEED_ADDRESS`）
- 导出逻辑：`scripts/_lib/export.ts`（`exportArtifacts`）
- 集成测试：`test/integration/SimpleLending.integration.ts`

## 3) 全栈岗（合约 + 前端 + 工程闭环）证据包

### 3.1 必演示步骤（8–10 分钟）

1) 三终端同时展示：node / deploy / frontend
2) UI 跑通完整流程：approve → supply → borrow → repay → withdraw
3) 演示“重启 node 导致地址失效”的坑，并用 deploy 重新导出修复（证明你懂工程）
4) 跑 `npm run smoke:e2e` 作为提交前自检

### 3.2 必截图/录屏证据（推荐集）

- 图 1：三个终端都在跑（node/deploy/frontend）
- 图 2：UI 已连接 + chainId=31337
- 图 3：Supply 成功（tx confirmed）
- 图 4：Borrow 后 healthFactor 变化（证明理解 LTV）
- 图 5：Repay/Withdraw 回到更安全状态（或解释为什么没回到）
- 图 6：smoke:e2e OK 输出

### 3.3 60 秒话术（面试开场）

- “这个仓库把题面拆成两条主线：工程线是 contracts→deploy→export ABI/地址；运行线是 useWallet 连接→useDashboard 读链→useActions 写链并触发刷新。”
- “我准备了两套验收：UI 现场演示（面试官可打勾）+ smoke:e2e 一键闭环自证（UI 翻车也能证明链路完整）。”

---

## 4) 提交/面试前 3 条检查（所有岗位通用）

1) 重启过 `hardhat node` 就必须重新跑 `deploy:localhost`（否则 deployments 地址必失效）
2) UI 出问题先跑 `smoke:e2e`：过了说明合约+导出大概率 OK
3) 任何“失败/卡住”，优先看 tx 状态机是否 stuck/替换交易，再看 normalizeError 的分类
