# 部署、导出、测试：这些脚本到底在做什么？

> 目标：你要能解释清楚：
> - 为什么要 deploy 脚本？
> - 为什么要导出 ABI 和地址？
> - 前端怎么拿到这些信息？
> - 测试到底在测什么？

---

## 1) 一键部署：scripts/deploy.ts

文件：`scripts/deploy.ts`

它做了 6 件事：
1) 读取当前网络 chainId（本地 Hardhat 默认 31337）
2) 部署两个 TestToken：USD8、WETH
3) 部署 SimpleLending，并把 token 绑定为 USD8（单币种借贷）
4) seed：给前 N 个本地账户发 USD8+WETH（方便 demo）
5) 可选 seed：从环境变量 `SEED_ADDRESS` 额外给一个地址发币（方便给你 MetaMask 地址）
6) 导出 artifacts（ABI + addresses）给前端

配图（部署与导出）：
```mermaid

  DEP[scripts/deploy.ts] --> D1[deploy USD8]
  DEP --> D2[deploy WETH]

  DEP --> EXP[exportArtifacts]

  EXP --> R1[deployments/31337.json]

  EXP --> R3[frontend/src/abis/TestToken.json]
  EXP --> R4[frontend/src/abis/SimpleLending.json]
```

## 2) 为什么必须导出 ABI/地址？

前端要和合约交互，必须知道两样东西：
1) 合约地址（address）
2) 合约接口（ABI）

没有地址：不知道“找哪个合约”。
没有 ABI：不知道“怎么编码函数调用”。

所以 `scripts/_lib/export.ts` 会把它们写到 `frontend/src/`。

---

## 3) exportArtifacts：写了哪些文件？

文件：`scripts/_lib/export.ts`

- `deployments/{chainId}.json`
  - 给仓库留存部署结果快照

- `frontend/src/contracts/deployments.json`
  - 给前端读：usd8/weth/lending 的地址 + chainId

- `frontend/src/abis/*.json`
  - 给前端读：TestToken、SimpleLending 的 ABI

写文件用 `scripts/_lib/fs.ts`：`ensureDir` + `writeJson`。

---

## 4) 前端怎么读这些部署结果？

- `frontend/src/contracts/deployments.ts` 读取 deployments.json
- `frontend/src/contracts/abis.ts` 读取 ABI json
- `frontend/src/contracts/contracts.ts` 用 provider new Contract
- `frontend/src/contracts/write.ts` 用 signer 连接后发交易

这就是“合约端 → 前端端”的桥。

## 5) 集成测试：test/SimpleLending.integration.ts

这份测试很关键，因为它证明：
- borrow/withdraw 的规则是合约 enforce 的，不是前端挡一挡。

覆盖点：

### 5.1 happy path
- approve → supply → borrow → approve → repay → withdraw
- 并且对每一步都断言事件 `.to.emit(lending, "Supplied")` 等

### 5.2 revert 用例
- 借超过 75% 会 revert："Exceeds borrowing limit"
- 借满后 withdraw 任意 amount 会 revert："Withdrawal would make position unhealthy"

### 5.3 pause/unpause
- owner pause 后 supply 会 revert："Pausable: paused"

### 5.4 为什么测试里用 getFunction("name")？

因为 ethers v6 + Hardhat 的类型推断有时会让 TS 报红。
`getFunction("...")(...args)` 既清晰又类型安全，也跟前端写模型一致。

你可以这样说：

"我做了 deploy 脚本，部署后会把 ABI 和地址导出到前端固定路径，所以任何人 fresh clone 后只要 `hardhat node` + `deploy`，前端就能自动拿到正确的合约信息，整个 demo 是可复现的。"
