## 0) 前端架构：读写分离（背下来）

- 读模型（Read model）：`useDashboard` + `contracts.ts`
  - 只用 provider
  - 负责读余额/池子/仓位
  - 负责事件驱动刷新 + backfill

- 写模型（Write model）：`useActions` + `write.ts` + `tx.ts`
  - 用 signer 发交易
  - 负责 approveIfNeeded、supply/withdraw/borrow/repay
  - 负责 tx 状态机与错误处理

## 1) 合约地址与 ABI 从哪里来？

### 1.1 deployments.json

- 文件：`frontend/src/contracts/deployments.json`
- 来源：`scripts/deploy.ts` 调用 `exportArtifacts()` 写入
- 内容：chainId + 三个合约地址（USD8/WETH/SimpleLending）

### 1.2 ABIs

- 文件：`frontend/src/abis/TestToken.json`、`frontend/src/abis/SimpleLending.json`
- 来源：Hardhat artifact 导出

### 1.3 在前端怎么用？

- `frontend/src/contracts/deployments.ts`：把 deployments.json 读成类型 Deployments
- `frontend/src/contracts/abis.ts`：把 json ABI 转成 ethers InterfaceAbi

## 2) 读链：getContracts + useDashboard

### 2.1 getContracts(provider)

文件：`frontend/src/contracts/contracts.ts`

作用：创建 3 个只读 Contract：
- `usd8`（TestToken）
- `weth`（TestToken）
- `lending`（SimpleLending）

这些 contract 只接 provider，所以不能发交易，只能 `balanceOf` / `getPoolInfo` 这种读。

### 2.2 useDashboard(provider, account)

文件：`frontend/src/hooks/useDashboard.ts`

它返回：
- `data`：DashboardSnapshot（余额 + pool + position）
- `loading/error`
- `refresh()`：立刻刷新
- `backfillEvents()`：回填最近 N 个区块的用户事件（兜底）

#### refresh() 读了哪些东西？

- `provider.getNetwork()`：验证 chainId
- `usd8.balanceOf(account)` / `weth.balanceOf(account)`
- `lending.getPoolInfo()`
- `lending.getUserPosition(account)`
- `lending.calculateMaxWithdraw(account)`
- `lending.calculateMaxBorrow(account)`

#### 为什么有 refreshSeq？

避免并发 refresh 的“后返回覆盖先返回”的问题（过期响应不写入 state）。

## 3) 实时更新：事件监听 + 节流 + backfill

### 3.1 事件监听（题目强制要求）

useDashboard 里对 lending 监听：
- Supplied/Withdrawn/Borrowed/Repaid

收到事件后，如果 event.user == 当前 account：触发 `scheduleRefresh()`。

### 3.2 节流 scheduleRefresh（250ms）

因为一个 tx 可能产生多个 log、或者 provider 重连导致 burst。节流防 UI 连刷。

### 3.3 backfillEvents（queryFilter 小范围）

如果事件订阅丢了（休眠/重连），我们还会在 `App.tsx` 的 block listener 里定期调用 backfillEvents：
- 只查最近 `EVENT_BACKFILL_MAX_BLOCKS`（runtime.ts 配置）
- 只查“跟当前用户有关”的事件（indexed user）

## 4) 钱包连接：useWallet（MetaMask + 自动切链）

文件：`frontend/src/hooks/useWallet.ts`

它做了 4 件事：
1) 判断 MetaMask 是否存在（window.ethereum）
2) connect：
   - `wallet_switchEthereumChain` 到 31337
   - 如果 4902（未添加网络）→ `wallet_addEthereumChain` 再切
   - `eth_requestAccounts` 请求连接
3) refresh：
   - `eth_accounts` 获取当前已连接账号
   - `eth_chainId` 获取 chainId
4) 监听 accountsChanged/chainChanged/connect/disconnect 自动 refresh

它还把连接状态写进 localStorage（connected/lastAccount），让刷新后体验更好。

## 5) 写链：useActions（交易流 + 可靠性）

文件：`frontend/src/hooks/useActions.ts`

它返回：
- `supply/withdraw/borrow/repay`
- `tx`：当前交易状态
- `refreshPendingTx/clearPendingTx`：stuck 的补救

### 5.1 金额解析：requireAmountStrict

- 来自 `utils/amount.ts`
- 只允许十进制（禁科学计数法），输出 bigint

这能避免新手最常见的“金额精度 bug”。

### 5.2 approveIfNeeded（Supply/Repay 必须）

流程：
1) 读 allowance(owner, spender)
2) 足够就返回 true
3) 不够就发 approve（exact 或 infinite）
4) 企业兼容：如果 direct approve 失败，尝试 approve(0) → approve(amount)

对应题目要求："Supply 之前必须 approve"。

### 5.3 withLock（防双提交）

每个动作 key（supply/withdraw/borrow/repay）都有 mutex，避免用户连点导致两笔交易。

### 5.4 runTxDetailed（核心交易状态机）

useActions 并不自己 wait receipt，而是把 “发交易 + 等确认 + 超时 + 替换” 交给 `state/tx.ts`。

TxStage：
- idle → signing → pending → confirmed
- pending → stuck（超时）
- pending → failed（revert/取消）

replacement：如果用户在钱包里 speed up，ethers 会抛 `TRANSACTION_REPLACED`，我们会追踪 replacement.hash。

### 5.5 页面刷新后恢复 pending

useActions 在 useEffect 里：
- 从 `state/txStore.ts` 读取 pending hash
- `provider.waitForTransaction` 继续等
- 超时标 stuck（不误判失败）

### 5.6 post-state 验证 verifyPostState（小白必懂）

交易 confirmed 不代表你的 RPC 读数据立刻一致。
所以 confirmed 后会短时间轮询 `getUserPosition`，确认 supply/borrow 等确实生效。
超时则标记 `unverified`，提示用户手动 Refresh。

## 6) Allowance 展示：useAllowance

文件：`frontend/src/hooks/useAllowance.ts`

它做了两件事：
1) 主动读 allowance
2) 监听 `Approval(owner, spender)` 事件刷新

并暴露 `refresh()`，在交易 confirmed 后强制同步（App.tsx 里会调用）。

## 7) App.tsx：把一切拼起来（UI 功能清单）

文件：`frontend/src/App.tsx`

你 UI 里所有功能点：
- Connect MetaMask 按钮
- Wrong network 提示 + 一键切 31337
- 显示三个合约地址（带 Copy/Show）
- Actions：Supply/Withdraw/Borrow/Repay
  - 每个按钮前都有 preflight 弹窗（让用户先看清：account、chainId、token、spender、approveMode）
- 显示 allowance + “Sufficient/Needs approve”
- 显示 Tx 状态（hash、error、post-state status）
- stuck 模式：Refresh status / Clear pending
- Max(safe) 按钮：maxBorrow/maxWithdraw 会减 1 wei 留余量（避免边界 revert）
- Fail-safe：当没有 pending tx 时，监听新区块每 3 秒刷新一次，并先 backfillEvents

## 8) 新手排障（你遇到问题看这里）

### Q1: 一直显示 Wrong network
- 看 `useWallet.ensureCorrectNetwork()` 是否成功
- 确认 Hardhat node 在 `http://127.0.0.1:8545`

### Q2: Supply 提示 Needs approve
- 说明 allowance < 你输入的 amount
- 你点 Supply 会先走 approve，再走 supply

### Q3: Tx 卡在 pending/stuck
- 点 stuck 面板的 Refresh status
- 如果你在 MetaMask speed up，系统会自动追踪 replacement hash
