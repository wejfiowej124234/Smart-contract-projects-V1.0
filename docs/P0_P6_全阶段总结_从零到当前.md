## 二、P0：必做项 100% + 企业级基础

**目标**：题目每一项都有对应实现且可自测；消除硬编码；建立设计令牌与 config；为布局打基础。

**做了什么**：

- **P0.1 设计令牌与配置**：`design-tokens`（或等价）→ `index.css` 的 `:root` 注入颜色、间距、圆角、字体、阴影；`config/ui.ts` 集中链名、appName、占位符、按钮/标签/错误映射（与 AppError.kind 一致）。组件与样式仅引用 `var(--*)` 或 config，禁止字面量色值/px/文案。
- **P0.2 题目必做项**：C 钱包与网络（MetaMask、切链、多链、持久化）；D 代币（USD8/WETH 余额、Approve 流程与 allowance 展示）；E 池子与仓位（5 项池子 + 5 项仓位含 HF 颜色）；F 四操作（Supply/Withdraw/Borrow/Repay，含校验与提示）；G 实时更新与交易状态（事件监听、确认后刷新、pending/confirmed/failed 展示）。
- **P0.3 企业级结构**：按「阶段零→一→二→三→四」顺序：类型定义（`types/dashboard.ts`）→ utils + config → 组件拆分（AddressDisplay、PoolOverview、UserPosition、ActionCard、TxStatus、Header、PreflightModal）→ useDashboardForm / useTxDisplay / usePreflight → App 瘦身（≤150 行，仅组合）。Hooks 顺序：useWallet → useDashboard → useTokenMetadata → useAllowance → useActions → useDashboardForm → useTxDisplay → usePreflight；onConfirmed 内 allowance.refresh + dashboard.refresh；contracts 仅用 `dashboard.contracts`。

**关键产出**：无硬编码、可实测全流程（连接→Supply→Borrow→Repay→Withdraw）、App 仅做组合。

**关键文件**：`frontend/src/index.css`（:root）、`config/ui.ts`、`types/dashboard.ts`、`utils/format.ts`、`utils/amount.ts`、各组件与 hooks、`App.tsx`。

**详细依据**：`docs/UI_DESIGN_P0_P1_P2_设计流程.md` 的 P0 节、阶段零～四；`docs/P0_AUDIT_REPORT.md`。

## 三、P1：Aave 风格布局与信息层级

**目标**：在 P0 基础上只做布局与视觉结构，不改变功能与数据流；信息层级与 Aave Dashboard 单市场视图一致。

**做了什么**：

- **P1.1 顶栏**：固定顶栏；左侧 appName（从 config）；右侧 Connect/Disconnect、网络（链名来自 config/network）、账户短码+复制/展开；样式用 token。
- **P1.2 主内容区**：池子概览（一张卡）、用户仓位（一张卡）、操作区四块（Supply/Withdraw/Borrow/Repay，每块含标题、金额输入、Max、主按钮，Supply/Repay 内 allowance 可见）；标签与数值分离、数值突出；卡片统一圆角/边框/内边距（token）；响应式至少可读可点。
- **P1.3 交易状态**：TxStatus 固定位置（如顶栏下方）；pending/confirmed/failed 必见；状态与错误文案来自 config，样式用 token。

**关键产出**：布局与信息层级符合 Aave 单市场观感；无新增硬编码。

**关键文件**：`Header.tsx`、`DashboardGrid`（含 PoolOverview、UserPosition、Balances）、`ActionCardsGrid`、`ActionCard`、`TxStatus`、`App.css`。

**详细依据**：`docs/UI_DESIGN_P0_P1_P2_设计流程.md` 的 P1 节；`docs/UI_DESIGN_设计流程_完成与下一步.md`。

## 四、P2：体验与可访问性增强

**目标**：深色模式、可访问性、微交互与加载态；不改变业务逻辑。

**做了什么**：

- **P2.1 深色模式**：design tokens 增加 dark 主题变量集；通过 `data-theme`（或 class）切换 `:root`；顶栏主题切换，状态持久化（如 localStorage）。

- **P2.3 微交互**：连接/刷新/交易有 loading 态；按钮/卡片 hover 用 token 过渡与阴影。

**关键产出**：主题可切换、可访问性达标、loading 与过渡统一。

**关键文件**：`index.css`（[data-theme]）、`Header.tsx`（主题按钮）、各组件 loading/aria/role。

**详细依据**：`docs/UI_DESIGN_P0_P1_P2_设计流程.md` 的 P2 节。

### 8.4 P6 后续优化（科技感增强，已实施）

在 P6 全面完成后，按「P6 完成度与科技感优化评估」建议实施的**可选增强**（不扩大范围）：

- **主按钮 hover 光晕**：深色主题新增 `--shadow-glow-primary-hover`（略强于默认 glow），主按钮 hover 时使用，浅色为 `none`。

- **刷新轻量反馈**：DataStatusBar 在 `loading` 时增加 class `statusBar--refreshing`，0.4s 主色 box-shadow 高亮后恢复。
- **利用率进度条过渡**：`.utilizationBarFill` 的 width 变化使用 `transition: width 0.25s ease`，数据更新更顺滑。
