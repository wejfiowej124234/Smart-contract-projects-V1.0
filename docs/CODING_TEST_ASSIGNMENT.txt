Coding Test Assignment (Web3 Javascript Engineer)

Test Overview
This test evaluates candidates' ability to build a functional React/TypeScript frontend for a DeFi lending protocol, demonstrating Web3 integration (ability to work with actual contracts, ABI integration, and real transaction handling), state management, and security awareness.
Candidates must build a React/TypeScript frontend that interacts with Solidity smart contracts deployed on a local Hardhat network / any EVM-compatible chains testnet. 
Project: Lending Protocol Dashboard
Time Limit: 5-7 days Tech Stack Required: React, TypeScript, ethers.js v6 
Test Requirements
Part 1: Smart Contract Setup (Mandatory)
1. Set up Hardhat project with provided contracts
2. Deploy contracts to local Hardhat network
3. Create deployment scripts that:  Deploy USD8 and WETH test tokens  Deploy SimpleLending contract  Seed test accounts with initial tokens
4. Export ABIs and addresses for frontend use
Part 2: Frontend Implementation (Mandatory) 
1. Wallet & Network Integration
 Connect to MetaMask (use ethers.js v6)  Handle chain network switching automatically. Switch to local Hardhat network
(chainId: 31337) / chosen EVM-compatible chains testnet  Persist connection state. Display connected account and network
2. Token Interaction
 Display user's USD8 and WETH balances  Implement "Approve" flow before supplying  Show approval status for lending contract

3. Lending Protocol Dashboard
 Connect to deployed SimpleLending contract  Display:
 Pool information (total supply, total borrow, utilization rate)  Current supply and borrow rates  User's supplied amount  User's borrowed amount  Health factor with color coding  Maximum withdrawable amount  Maximum borrowable amount
4. Transaction Functions
 Supply: Deposit USD8 into protocol (with approval check)  Withdraw: Withdraw supplied USD8 (with health factor check)  Borrow: Borrow USD8 against collateral (with health factor and liquidity
check)  Repay: Repay borrowed USD8
5. Real-time Updates
 Update balances after transactions  Listen for contract events and update UI  Display transaction status (pending, confirmed, failed)
Part 3: Testing & Quality - Bonus (Optional)
You can work on all or part of following:
1. Write at least 2 integration tests for contract interaction
2. Implement proper error handling for:
 Insufficient balance  Insufficient allowance  Health factor violations  Network errors
3. Add loading states for all async operations
